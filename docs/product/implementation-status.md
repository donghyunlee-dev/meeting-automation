# 현재 구현 기준

> 이 문서는 저장소 코드에서 확인한 동작을 설명합니다. 기준 커밋: `5b3375b` (2026-10-21). PRD, 설계안, 과거 TASK/evidence와 동작이 다르면 이 문서와 실제 코드를 기준으로 읽고, 제안·취소된 설계는 현재 기능으로 간주하지 않습니다.

## 서비스 구성

- `frontend/`는 React 19, TypeScript, Vite 기반 모바일 웹 앱입니다. 브라우저가 마이크를 확인하고 녹음하며, 오디오 조각을 백엔드에 직접 보냅니다.
- `backend/`는 Java 25, Spring Boot REST API입니다. 세션 처리, 오디오 조립, OpenAI 호출, 문서 저장, 이메일과 Slack 전달을 담당합니다.
- Vercel은 정적 프런트엔드 배포 대상이고 Render는 백엔드 배포 대상입니다. 배포 코드와 로컬 실행 구성이 존재한다는 사실은 특정 운영 배포가 현재 정상이라는 증거가 아닙니다.
- 업무 데이터베이스, Redis, 외부 작업 큐는 사용하지 않습니다. 진행 중 세션과 작업 상태는 백엔드 메모리에 있습니다.

## 회의 흐름

1. 사용자는 Notion 또는 Confluence를 연결하고 기본 페이지 구조를 초기화합니다.
2. 새 회의에서 제목, 날짜, 참석자, 기본 회의록 템플릿을 지정합니다. 브라우저는 마이크 입력을 먼저 확인한 뒤 녹음을 허용합니다.
3. 녹음 중 `MediaRecorder`가 오디오 조각을 만들고, 프런트엔드가 조각을 백엔드 API로 업로드합니다. 백엔드는 임시 파일로 조각을 보관하고 처리 때 합칩니다.
4. 백엔드는 OpenAI Audio Transcriptions API에 한국어 오디오를 보내 전사와 화자 구간을 받습니다. 기본 모델은 `gpt-4o-transcribe-diarize`, 응답 형식은 `diarized_json`입니다.
5. 백엔드는 전사 결과와 선택 템플릿을 사용해 회의록 초안을 구조화합니다. 기본 모델은 `gpt-6-luna`이며, Chat Completions Structured Outputs(JSON Schema)를 사용하고 회의록 문장에 전사 구간 근거를 연결합니다.
6. 사용자는 화자와 참석자를 매핑하고, 회의록의 요약·논의·결정·실행 항목 등을 확인·수정합니다. 매핑 및 회의록 수정은 검토 화면에서 각각 저장합니다.
7. 사용자가 검토 완료를 실행하면 백엔드는 확정된 회의록과 선택 템플릿을 문서 작성 모델에 전달합니다. 모델은 템플릿 제목·섹션 순서에 맞춘 Markdown 본문을 만들고 Notion 또는 Confluence에 저장합니다.
8. 문서 저장이 성공한 뒤에만 설정된 Gmail 이메일과 Slack 알림을 각각 전달합니다. 회의 결과 화면은 문서 저장 및 각 채널의 성공·실패를 따로 보여주며 안전한 실패는 다시 시도할 수 있습니다.

처리 중 오류는 실패한 단계와 안전한 오류 코드로 표시됩니다. 전사/회의록 초안 생성 실패 시 재시도 정책에 따라 원본 오디오를 임시 보존합니다. 초안 생성이 성공하면 최종 문서 저장 전에 오디오를 삭제합니다.

## AI 요청의 실제 역할

| 단계 | API / 기본 모델 | 입력과 결과 |
|---|---|---|
| 음성 인식·화자 구간 | OpenAI Audio Transcriptions API / `gpt-4o-transcribe-diarize` | 한국어 오디오 입력, `diarized_json` 전사·화자 구간 반환 |
| 회의록 초안 | OpenAI Chat Completions API / `gpt-6-luna` | 회의 템플릿, 회의 정보, 참석자, 전사와 근거 구간 ID를 입력하고 구조화된 회의록 반환 |
| 문서 본문 작성 | OpenAI Chat Completions API / `gpt-6-luna` | 선택한 템플릿과 사용자가 검토한 회의록만 입력하고 템플릿 형식의 Markdown 반환 |

모델 ID와 제한 시간은 백엔드 설정으로 바꿀 수 있습니다. OpenAI 키는 브라우저 설정이 아니라 백엔드 환경 설정에 둡니다.

## 문서 연결과 저장 위치

문서 초기화는 사용자가 명시적으로 시작합니다. 루트 `Meeting Automation` 아래에 `Meetings`, `Participants`, `Meeting Data`, `Templates` 페이지를 준비하고 기본 회의록 템플릿을 `Templates`에 기록합니다. `Home` 및 `Speaker Memory` 기본 페이지는 현재 초기화 구조에 없습니다.

| 정보 | 현재 저장 방식 |
|---|---|
| 문서 연결 입력과 복구 정보 | 브라우저 `localStorage`에 저장. 같은 브라우저 프로필에서 백엔드 설정 복구에 사용되며 기기 간 동기화되지 않음 |
| Slack·이메일 설정 복구 정보 | 브라우저 `localStorage`에 저장하고, 백엔드 설정 API로 복구 |
| 백엔드 문서·Slack·이메일 연결 설정 | 로컬은 `DOCUMENT_SETTINGS_DIR`와 암호화 키를 설정하면 AES-GCM 암호화 파일, 그 외에는 프로세스 메모리. Render 프로필은 메모리 저장소 사용 |
| 회의 세션·처리·전달 상태 | 백엔드 프로세스 메모리. 백엔드 재시작 시 진행 중 상태 복원은 보장하지 않음 |
| 오디오 조각 및 조립본 | 백엔드 `TEMP_AUDIO_DIR`의 임시 파일. 영구 오디오 저장소가 아님 |
| 참석자·템플릿·완료 회의 문서 | 연결된 Notion 또는 Confluence 페이지 |

브라우저 `localStorage`의 복구 데이터에는 서비스 자격 증명이 포함될 수 있습니다. 이는 서버 간 동기화나 기기 간 백업이 아니며, 브라우저 프로필의 저장 데이터에 접근하는 사람에게 노출될 수 있으므로 공유 기기 사용을 피하고 브라우저 저장소를 보호해야 합니다.

## 연결 및 알림

- Notion은 내부 Integration token과 부모 페이지 위치를 사용합니다. Confluence Cloud는 사이트, space ID, 선택적 부모 페이지 위치와 API token을 사용합니다.
- Gmail OAuth 2.0 정보와 Slack Incoming Webhook은 앱 설정 화면에서 저장·수정·삭제할 수 있습니다. 저장 후 설정 확인이 진행되며 비밀값은 다시 마스킹되어 표시됩니다.
- 연결 확인 상태는 실제 연동 요청 결과에 기반합니다. 상태 조회만으로 외부 서비스에 시험 메시지를 보내지는 않습니다.
- 이메일에는 저장된 회의록의 Markdown 문법을 HTML 본문으로 변환해 전달합니다. Slack에는 회의 완료 알림을 보냅니다.

## 개발 실행

필요 환경은 Node.js 24, npm, JDK 25입니다. 저장소 루트에서 각각 별도 터미널로 실행합니다.

```bash
cd backend && ./gradlew bootRun
```

```bash
cd frontend && npm ci && npm run dev
```

프런트엔드 개발 서버는 보통 `http://localhost:5173`, 백엔드는 `http://localhost:8080`에서 실행합니다. Vite는 `/api` 요청을 로컬 백엔드로 전달합니다. 실제 AI·문서·이메일·Slack 연동을 시험하려면 각 Provider의 유효한 설정이 필요합니다. 백엔드는 Spring Boot가 자동으로 읽지 않는 `.env` 파일을 사용하지 않습니다.
