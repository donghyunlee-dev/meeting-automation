# TASK-022.07 구현 계획

> 선행: TASK-022.06 완료. 사용자 요청으로 화면 사용성 개선을 다음 독립 작업보다 먼저 수행한다.

## 변경 범위와 책임

Frontend의 `DocumentSetupWizard` 안내 콘텐츠와 `app.css` 반응형 스타일, 직접 영향받는 컴포넌트 검증을 수정한다. API 클라이언트와 Backend는 바꾸지 않는다.

## 구현 순서

1. 현재 최초 연결 화면을 360px 폭에서 확인하고, Provider 전환 버튼과 하단 고정 메뉴가 만드는 레이아웃 문제를 재현한다.
2. Notion/Confluence별 준비 단계를 짧은 번호 목록으로 정리한다. 발급 위치와 대상 페이지/공간에 연결을 허용하는 단계 및 권한을 각각 구분하고 공식 도움말 링크를 제공한다.
3. 입력 폼의 비밀정보가 테스트 후 지워지고 브라우저 저장소에 저장되지 않는다는 안내, 연결 테스트는 검사용 페이지를 만들지 않으며 실제 쓰기 권한은 초기 구조 생성에서 확인된다는 안내를 배치한다.
4. 모바일 우선 간격, 한 열 카드 배치, 한국어 단어 단위 줄바꿈, 버튼 라벨의 줄바꿈 방지, 하단 메뉴 높이만큼의 스크롤 안전 여백을 적용한다.
5. 기존 워크플로 검증과 360px 브라우저 화면 검토를 수행하고 `docs/evidence/TASK-022.07/verification.md`에 정확한 head와 결과를 기록한다.

## 완료 기준

- 360px에서 가로 스크롤, 잘리거나 어색하게 줄바뀐 버튼 문구, 하단 메뉴에 가려진 입력/동작이 없다.
- 두 Provider 각각 처음 준비하는 사용자가 token/계정, 부모 위치/Space ID, 접근 권한을 안내만 보고 준비할 수 있다.
- 양쪽 Provider의 입력·전환·테스트 등 기존 동작과 `/settings/document` 재사용이 유지된다.
- 선택된 프론트엔드 검증과 실제 모바일 폭 브라우저 검토를 Evidence에 기록한다.
